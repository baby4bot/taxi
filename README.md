## 📖 โปรแกรมนี้คืออะไร

เว็บแอปหน้าเดียว (Single-file Web App) ที่เปลี่ยนมือถือให้เป็น **มิเตอร์แท็กซี่** สำหรับคนขับ
ใช้งานบนหน้ารถจริง — ค้นหาปลายทาง → ประเมินราคาและระยะทาง → นำทาง → จับเวลามิเตอร์
→ ออกใบเสร็จให้ผู้โดยสาร พร้อมระบบสมาชิก/สิทธิ์สำหรับสหกรณ์หรือกลุ่มคนขับ

ออกแบบมาให้ **เปิดค้างไว้ตอนขับได้จริง**: จอเต็ม, ตัวอักษรใหญ่, ปุ่มกดง่าย,
ทำงานต่อได้แม้สลับไปใช้ Google Maps หรือปิดแอปไปแล้ว

## ✨ ฟีเจอร์หลัก

### 🚕 ฝั่งคนขับ (ใช้งานหน้ารถ)

- 🧮 **คำนวณค่าโดยสารอัตราก้าวหน้า** — กรอกระยะทางเอง หรือให้ระบบดึงระยะจากเส้นทางจริง
  เลือกได้ว่าขับ **รถปกติ (35฿)** หรือ **แวน (40฿)**
- 🔍 **ค้นหาปลายทางแล้วประเมินทันที** — ได้ทั้งระยะทาง / เวลา / ราคา / เวลาถึงโดยประมาณ
  (ใช้ **TomTom Search + Routing** ที่คิดเวลารถติดจริง ไม่ใช่แค่ระยะเส้นตรง)
- 📍 **หน้าสรุปเส้นทางก่อนเริ่ม** — ตรวจปลายทางให้ชัดก่อนกดเริ่ม ไม่กดผิดที่
- ▶️ **จับเวลามิเตอร์ (Meter)** — เปิดแล้วนับ **เวลาวิ่ง / เวลารถติด / ระยะทางที่วิ่งจริง** จาก GPS
  มีปุ่ม **หยุดชั่วคราว** และปุ่ม **จบเที่ยว**
- 🧭 **ปุ่มนำทาง Google Maps ในตัว** — ส่งต่อจุดหมายให้ Google Maps นำทางด้วยคำสั่งเดียว
  (คนขับใช้ Google Maps นำทางไปได้เลย แล้วกลับมาเข้าแอป มิเตอร์ยังนับต่อ)
- 🗺️ **แผนที่นำทางขนาดย่อ (Mini Map)** — แผนที่ลอยอยู่มุมจอที่โชว์ **ตำแหน่งรถบนเส้นทาง** แบบที่เห็นใน Google Maps:
  แผนที่โหมดมืดอ่านง่าย · เส้นทางสีน้ำเงิน (ช่วงที่วิ่งผ่านแล้วเป็นสีจาง) · หมุดจุดหมาย · หัวรถเป็นลูกศรหมุนตามทิศที่วิ่งจริง ·
  เลื่อนตามรถเองอัตโนมัติ พร้อมบอก **ระยะทางที่เหลือ + เวลาถึงโดยประมาณ** และแถบความคืบหน้าของเที่ยว ·
  **บอกจุดเลี้ยวถัดไป** — ไอคอนลูกศรบอกทิศ (เลี้ยวซ้าย/ขวา · หัก · ชิด · กลับรถ) + ระยะถึงจุดเลี้ยว และจุดหมุดบนเส้นทาง
  (คำนวณจากรูปทรงเส้นทางเอง จึงใช้ได้กับเที่ยวที่กู้คืนมาด้วย) — เลยจุดเลี้ยวสุดท้ายแล้วจะเป็น "ตรงไปจนถึงจุดหมาย" ·
  **เตือนล่วงหน้าด้วยเสียง + สั่น** — ไกล ~300 ม. (2 จังหวะนุ่ม ๆ) และใกล้ ~80 ม. (3 จังหวะถี่กว่า) เตือนระดับละครั้งเดียวต่อจุดเลี้ยว
  (จอดติดอยู่ตรงนั้นก็ไม่ดังซ้ำ) · เคารพสวิตช์ปิดเสียง/ปิดสั่นในหน้าโปรไฟล์ · ซ่อน Mini Map = เงียบ ·
  **ลากย้ายได้ทั้งก้อน** (จำตำแหน่ง/ขนาดไว้) · ย่อ–ขยายได้ 2 ขนาด · ลากแผนที่เอง/หุบนิ้วเพื่อซูม แล้วกด `◎` กลับมาที่รถ ·
  ปุ่ม `✕` ซ่อนได้ — เปิดกลับมาเองทุกครั้งที่เริ่มเที่ยวใหม่หรือกดเริ่มต่อเที่ยวค้าง และปิดเองเมื่อจบเที่ยว
  ปุ่ม `✕` ซ่อนแผนที่แล้ว **เปิดกลับได้ทันทีระหว่างเที่ยว**: มีปุ่ม 🗺️ “เปิดแผนที่นำทาง” โผล่ในแถบ
  “📍 ไปที่: จุดหมาย” ทั้งจอมิเตอร์ปกติและจอมิเตอร์ใหญ่ — กดแล้วแผนที่กลับมาโชว์เส้นทาง/ตำแหน่งรถต่อจากเดิม
  (ปุ่มจะหายเองเมื่อแผนที่กลับมาแสดง หรือเมื่อจบเที่ยว)
- 🛣️ **ค่าทางด่วน / ค่าบริการเพิ่ม** — เพิ่ม–ลบรายการได้ระหว่างเที่ยว ระบบจำค่าที่ใช้ล่าสุดไว้
  เลือกโหมด **เลี่ยงทางด่วน** หรือ **ขึ้นทางด่วน** ได้ — หน้าสรุปกับตอนนำทางใช้ข้อมูลชุดเดียวกัน
  (สลับเป็นขึ้นทางด่วนกลางเที่ยวได้ ระบบขอเส้นทางขึ้นด่วนใหม่ทันที พร้อมอัปเดตค่าทางด่วน/เส้นทางบนแผนที่ย่อให้ตรงกัน)
  **สลับแล้วบอกผลต่างทันที** — “สั้นลง 3.1 กม. · เร็วขึ้น 14 น. · ค่าทางด่วน +100฿” (หรือ “ไกลกว่าเดิม/ช้าลง/ประหยัดค่าทางด่วน …” ในทางกลับกัน)
  · ถ้าเส้นทางนั้นไม่มีทางด่วนจริง จะแจ้งเตือนและกลับไปใช้เส้นทางปกติให้เอง

- 🧾 **ใบเสร็จให้ผู้โดยสาร** — สร้างเป็น **รูปภาพ PNG** ดาวน์โหลด/แชร์ได้ พร้อม QR Code

| ช่วงระยะทาง | อัตราต่อ กม. |
|---|---|
| กิโลเมตรแรก | รวมอยู่ในค่าเริ่มต้น |
| 2 – 10 กม. | 6.50 ฿ |
| 11 – 20 กม. | 7.00 ฿ |
| 21 – 40 กม. | 8.00 ฿ |
| 41 – 60 กม. | 8.50 ฿ |
| 61 – 80 กม. | 9.00 ฿ |
| มากกว่า 80 กม. | 10.50 ฿ |

## 🛠 เทคโนโลยี

- **Frontend:** HTML + CSS + JavaScript เขียนรวมในไฟล์เดียว (**ไม่มี build step, ไม่มี dependency ในเครื่อง**)
- **Backend / ฐานข้อมูล:** **Firebase Firestore** (สมาชิก, สิทธิ์, ประวัติการใช้งาน, ประวัติเวอร์ชัน)
- **แผนที่ / เส้นทาง:** **TomTom API** (Search + Routing ที่คิดรถติด), **Google Maps Deep Link** (นำทางจริง)
- **PWA:** Service Worker (`sw.js`) + Web App Manifest — ติดตั้งเต็มจอเหมือนแอป
- **UI:** Google Fonts (**Kanit** + Material Symbols), SortableJS (ลากเรียงลำดับ), Canvas (วาดรูปใบเสร็จ)

## 🧬 เบื้องหลังที่คนแก้โค้ดควรรู้

สามเรื่องนี้แก้บ่อยที่สุด และแตะผิดจุดเดียวจะเห็นผลทันทีบนหน้าจอจริง

### 🎨 ระบบธีม (3 โหมด)

- ธีมถูกกำหนดที่แท็ก `<html>` เป็น **คลาสเดียว**: `dark` (ค่าเริ่มต้น) · `oled` (ดำสนิท) · `light` (สว่าง)
- สีทั้งหมดอยู่ใน **CSS Variables** ที่ `:root` และแต่ละธีมมีบล็อกทับสีของตัวเอง (เช่น `html.light { … }`)
  — **ทับเฉพาะชุดสี ไม่แตะเลย์เอาต์/ขนาด** ขนาดปุ่ม ระยะห่าง และตำแหน่งทุกจอจึงเท่ากันทั้ง 3 ธีม
- ตัวคุมอยู่ใน JS: `THEME_ORDER = ['dark','oled','light']` · `applyThemeMode(mode, opts)` ·
  `setThemeMode()` · `cycleThemeMode()` · `syncThemeUi()`
- ปุ่มสลับที่หน้าแรก **วนตามลำดับ** (มืด → ดำ OLED → สว่าง) พร้อมไอคอนบอกโหมด (พระจันทร์ / พระจันทร์มีดาว / ดวงอาทิตย์)
  และในหน้าโปรไฟล์เลือกตรงได้ 3 ปุ่ม
- เก็บค่าที่ **Firestore `users/<uid>.themeMode`** (ซิงก์ข้ามทุกเครื่องของคุณ) + เขียน `oledMode` ควบคู่ไว้ให้บิลด์เก่าอ่าน
  · `localStorage` เป็นสำรองตอนออฟไลน์ · เปลี่ยน `<meta name="theme-color">` ของเบราว์เซอร์ตามธีมด้วย
- **เพิ่มธีมใหม่** = เพิ่มคลาส + บล็อกทับสี แล้วต่อท้าย `THEME_ORDER` — ไม่ต้องแก้โค้ดส่วนอื่น

### 🚀 หน้าจอโหลด (Loading Screen) — รูปตั้งได้จากแอดมิน (เพิ่ม 14 ก.ย.)

ตอนเปิดแอป / หลังล็อกอิน จะมีจอโหลดที่ **รูปพื้น + ข้อความ + แถบความคืบหน้า + เปอร์เซ็นต์**
ตาหน้าเดียวกันทุกเครื่อง เพราะค่าเก็บที่ **`settings/loading_screen`** (ค่าที่ใช้ร่วมกัน ไม่ใช่ค่าส่วนตัวของใคร)

| ส่วน | รายละเอียด |
|---|---|
| เก็บค่าที่ไหน | Firestore `settings/loading_screen` → `image` (data URL) · `title` · `updatedAt` · `updatedBy` |
| แคชในเครื่อง | `localStorage.taxi_loading_screen_v1` → เปิดแอปครั้งถัดไปเห็นรูปของแอดมิน **ทันที** ไม่ต้องรอเน็ต |
| ใครตั้งได้ | แอดมิน (`Admin`) หรือผู้มีสิทธิ์ `canManageToastMsg` — ทาง **ตั้งค่าการใช้งาน → ⚙️ บริการ/ระบบ → หน้าจอโหลด** |
| อัปโหลดรูป | ย่อเป็น **720×1280 JPEG ≤ 320 KB** ให้เองก่อนบันทึก (เอกสาร Firestore ต้องไม่เกิน 1 MiB) |
| ดาวน์โหลด / ลบ | มีทั้งคู่ — “ลบรูป” = กลับไปใช้พื้นสำเร็จรูปของแอป |
| ทดลองดู | ปุ่ม “ทดลองดู” โชว์จอโหลดจริง ~2.8 วินาที ก่อนกดบันทึก |

**กติกาที่ห้ามพลาด (รวมบทเรียนจากเคสจริง 14 ก.ย.):**

- **ห้ามปิดจอโหลดด้วย `appLoader.style.display = 'none'` ในเส้นทางปกติ** — ให้เรียก `window.__lds.finish()`
  (วิ่งถึง 100% แล้วจางหาย) หรือ `window.__lds.forceHide()` (ซ่อนทันที/ตอนระบบพัง) ไม่งั้นจะไม่เห็นแถบความคืบหน้า
  · ยกเว้น **NUCLEAR FALLBACK 10 วินาที** ที่ตั้งใจให้ซ่อนทึบเสมอ
- **ทุกการซ่อนมี “รุ่น” (`gen`)** — `restart()` เพิ่มรุ่น ทำให้คิวซ่อนของรอบเก่าถูกยกเลิก
  (บั๊กที่เจอตอนทดสอบ: กด “ทดลองดู” ซ้ำเร็ว ๆ แล้วจอโหลดถูกคิวเก่าซ่อนทิ้งกลางทาง)
- **สคริปต์หน้าจอโหลดอยู่ “ก่อน” ตัวจอโหลดใน DOM** (บรรทัด ~1810 vs ~2080) → การทารูปต้องทำ **3 จุด**:
  ① ตอนอ่านแคช ② เมื่อ `DOMContentLoaded` ③ ที่ท้าย `<body>` ก่อนเรียก `loadLoadingScreenConfig()`
  ไม่งั้นจะเจอเคส **“รีเฟรชแล้วรูปไม่ขึ้น”** (ทาไม่เจอ element แล้วเงียบ ๆ ไป)
- **ใช้ `<img>` ไม่ใช่ CSS `background-image`** — จุดสำคัญคือ **ตรวจสอบได้จริง** ว่าเบราว์เซอร์ถอดรหัสแล้ว
  (`naturalWidth > 0`) และ data URL ขนาด 150–300 KB ใน background-image มีโอกาสถูกมองข้ามแบบเงียบ ๆ
- **ทุกชั้นของจอโหลดต้องมี `z-index` กำกับ** — รูป(1) → พื้นสำเร็จรูป(0) → ม่านเงา(2) → ข้อความ(3)
  ถ้าปล่อยให้เรียงตามลำดับ DOM เฉย ๆ ชั้นพื้นทึบที่อยู่ทีหลังจะ **วาดทับรูป** (อาการ: “รูปติดตั้งแล้วแต่ไม่ขึ้น”)
  · ตัวตรวจในหน้าตั้งค่ามีบรรทัด **“รูปไม่ถูกชั้นอื่นบัง”** ที่เช็ค `elementsFromPoint` จริง ไม่ใช่ดูแค่ค่าในตัวแปร
- **ยิงคำขอค่าหน้าจอโหลดจาก “ต้นไฟล์”** (พร้อม `preconnect` ไป firestore.googleapis.com) — ไม่งั้นค่ามาถึงช้า ~2.5 วิ
  แล้วจอโหลดปิดไปก่อน · เครื่องใหม่ที่ยังไม่มีแคชจะ **รอสูงสุด 2.2 วิ** และให้เห็นรูป ~0.9 วิ ก่อนปิด
  (เครื่องที่มีแคช: รูปขึ้นใน ~0 ms และปิดที่ ~0.7 วิ — ไม่หน่วงเลย)
- **“ทดลองดู” = ค้างที่ 100% จนกว่าจะแตะปิด** (มีข้อความ “แตะตรงไหนก็ได้เพื่อปิด” + ประตูนิรภัย 60 วิ)
  แล้วกลับเข้าหน้าตั้งค่าเดิม — ห้ามเด้งกลับเองแบบเดิม
- เพิ่มขั้นตอนจริงได้ด้วย `window.__lds.step(40, 'กำลังโหลด...')` — แถบวิ่งเองถึง 92% แล้วรอสัญญาณ “พร้อม” จริง
- **ตัวตรวจที่ใช้ได้ทันที:** `window.__ldsState()` (รูปมาจากไหน/ถอดรหัสได้ไหม/เขียนแคชได้ไหม) ·
  `window.__ldsTrace` (ลำดับการทา) · `window.__ldsHiddenAt` (เวลาที่จอโหลดปิด) — ไม่ต้องเดาอีก
- ดึงค่าล่าสุดตอนบูตที่ `window.loadLoadingScreenConfig()` (เรียกก่อน `listenAppConfig()`) — เอกสารยังไม่มี = 404 เป็นเรื่องปกติ

### 🎴 การ์ด QR Code รับเงิน ในหน้าตั้งค่าโปรไฟล์ (เพิ่ม 14 ก.ย.)

หน้าอัปโหลด QR ถูกปรับให้ **หน้าตา/ปุ่มชุดเดียวกับหน้าจอโหลด** — กล่องพรีวิว + ข้อความขนาดรูป + ปุ่ม 4 ปุ่ม

| ส่วน | รายละเอียด |
|---|---|
| เก็บค่าที่ไหน | Firestore `users/{uid}.qrCodeURL` — ค่าส่วนตัวของคุณ (ไม่ใช่ค่าที่ใช้ร่วมกัน) |
| พรีวิว | กล่อง 1:1 พื้นขาว (`.qr-card-paper`) เห็นชัดว่า QR อ่านได้ · **แตะในกรอบ = เปลี่ยนรูปทันที** |
| ปุ่ม | **สัญลักษณ์ล้วน 4 ปุ่มเรียงแถวเดียว** (มี `title`/`aria-label` เป็นคำอธิบาย): อัปโหลด · ดาวน์โหลด · ดูรูปเต็ม (ยื่นจอให้น้องสแกน แตะตรงไหนก็ปิด) · ลบ (ถังขยะ สีแดง) |
| ขนาดรูป | บอกเป็น KB จริงจาก data URL · ฝั่งบันทึกย่อเป็น **ไม่เกิน 800×800 JPEG** (พื้นขาว กัน QR พื้นโปร่งใส) |
| สิทธิ์ | ปุ่ม “อัปโหลดรูป” ซ่อนเมื่อไม่มี `canEditOwn` · ปุ่ม “ลบรูป” ต้องมี `canDeleteMedia` (เหมือนเดิม) |
| กันกดพลาด | กด “ดาวน์โหลดรูป” ตอนยังใช้ไอคอนตัวอย่าง = เตือนว่า “ยังไม่มีรูป QR ให้ดาวน์โหลด” |

**กติกาที่ห้ามพลาด:** อย่าลบ/เปลี่ยน id ของ `editQrCodePic` · `uploadQrInput` · `delOwnQrPicBtn` · `qrPicHint`
เพราะตรรกะบันทึกโปรไฟล์ (เทียบกับ `window.DEFAULT_QR`) และ `applyPermissionsUI` ผูกกับ id เหล่านี้อยู่

### 🆕 สมาชิกใหม่ (รายวัน) — แอดมินรู้ว่าใครสมัครเข้ามา (เพิ่ม 14 ก.ย.)

เมนูใหม่ใน **ตั้งค่าการใช้งาน → สมาชิก / สิทธิ์ → “สมาชิกใหม่”** (สิทธิ์เดียวกับ `canViewUsers`)

| ส่วน | รายละเอียด |
|---|---|
| สรุปด้านบน | **วันนี้ · 7 วันล่าสุด · 30 วันล่าสุด · รวมทั้งหมด** (นับเฉพาะบัญชีที่รู้วันสมัคร) |
| รายการ | การ์ดรายวัน เรียงใหม่ → เก่า · หัวข้อแบบ “วันนี้ · 14 ก.ย. 2569” + จำนวน “+ N คน” |
| ข้อมูลแต่ละคน | รูป · ชื่อที่แสดง · ป้ายบทบาท · @ชื่อผู้ใช้ · เวลาสมัคร · เบอร์โทร · ทะเบียนรถ · สถานะถูกระงับ |
| วันสมัครมาจากไหน | ฟิลด์ **`createdAt`** ที่เขียนตอนสร้างบัญชี (สมัครเอง / แอดมินเพิ่ม / admin เริ่มระบบ) |
| บัญชีเก่า | ไม่มี `createdAt` → อ่านจากบันทึก **“สมัครสมาชิก”** ใน `global_logs` · ไม่พบเลย → ย้ายไปกลุ่ม **“ไม่ทราบวันสมัคร”** พร้อมชิป “เข้าใช้ล่าสุด” (ไม่เดาวันให้) |

**กติกาที่ห้ามพลาด:**

- **ห้ามแก้ `createdAt` ของบัญชีที่มีอยู่แล้ว** — เป็นวันสมัครจริง ใช้ตรวจย้อนหลังได้
- **ห้ามใช้ฟิลด์ `order` เป็นวันสมัคร** — `order` ถูกเขียนใหม่ทั้งคอลเลกชันทุกครั้งที่แอดมินลากสลับลำดับผู้ใช้
- การอ่าน `global_logs` ให้จำกัด **300 รายการล่าสุด** และข้ามทันทีถ้าทุกบัญชีมี `createdAt` ครบ (ประหยัดโควตา)

#### 🗓️ กำหนดวันสมัครย้อนหลัง (สำหรับบัญชีที่ขึ้นว่า “ไม่ทราบวันสมัคร”)

| ประเด็น | รายละเอียด |
|---|---|
| ปุ่มอยู่ตรงไหน | ใต้การ์ดสมาชิกในกลุ่ม **“ไม่ทราบวันสมัคร”** — ปุ่ม **“กำหนดวันสมัคร”** (เห็นเฉพาะคนมีสิทธิ์) |
| ใครกดได้ | `canSetSignupDate()` = **Admin** หรือมีสิทธิ์ **`canEdit`** (แก้ไขสมาชิก) |
| กรอกอะไร | **วันที่** (มีปุ่มลัด วันนี้ / เมื่อวาน / -7 วัน) + **เวลาโดยประมาณ** (ใช้เรียงลำดับในวันนั้น) |
| ระบบเขียนอะไร | `users/{uid}.createdAt` + **`createdAtSetBy`** (ชื่อคนกำหนด) + **`createdAtSetAt`** — merge เฉพาะ 3 ฟิลด์นี้ ไม่แตะข้อมูลอื่น |
| หลักฐานในรายชื่อ | การ์ดนั้นจะได้ชิป **“กำหนดโดย: <ชื่อ>”** และย้ายไปอยู่ในกลุ่มวันจริงทันที |
| ด่านกันพลาด | วันในอนาคต → บล็อก · ไม่ได้เลือกวันที่ → เตือน · บันทึกไม่สำเร็จ → toast แดง (ไม่เงียบ) |
| ไม่กินโควตา | หลังบันทึก อัปเดตในหน่วยความจำแล้วเรนเดอร์ซ้ำ — **ไม่ยิงอ่าน Firestore ใหม่** |

#### 🔔 แจ้งเตือนทันทีเมื่อมีคนสมัครใหม่ (ไม่กินโควตาอ่านเพิ่ม)

แอดมินจะได้ **เสียง + สั่น + ป้าย “ใหม่ N”** ทันทีที่มีคนสมัคร — แตะที่ป้ายหรือ toast เพื่อเปิดดูรายชื่อได้เลย

| ประเด็น | รายละเอียด |
|---|---|
| กลไก | `onSnapshot` บน `global_logs` โดยกรอง `action == "สมัครสมาชิก"` + `limit(3)` |
| ต้นทุนการอ่าน | **3 ครั้ง** ตอนเริ่มฟัง (เฉพาะบัญชีที่มี `canViewUsers`) + **1 ครั้งต่อการสมัคร 1 ครั้ง** — เครื่องคนขับทั่วไป **ไม่ฟังเลย** (0 ครั้ง) |
| ไม่ต้องทำอะไรใน Console | ใช้ของเดิมที่มีอยู่แล้ว — **ไม่ต้องแก้ Firestore Rules / ไม่ต้องสร้าง index** |
| ตอนเปิดแอปแล้วเจอของค้าง | เตือนแบบ **เงียบ** (ไม่มีเสียง/สั่น) + ป้าย “ใหม่ N” ค้างไว้จนกดดู |
| ตอนสมัครสด ๆ ระหว่างใช้งาน | toast **ทอง** = เสียงติ๊ง + สั่น (ตามสวิตช์ในหน้าโปรไฟล์: `toastSound` / `vibrateGold`) |
| รับรู้แล้วหาย | เปิดหน้าต่าง “สมาชิกใหม่” = ล้างป้าย (`localStorage.taxi_signup_seen_v1`) |
| เงื่อนไขพ่วง | ต้องเปิด log ประเภท **“สมัครสมาชิก”** ไว้ (ค่าเริ่มต้นเปิด) — ถ้าปิด การแจ้งเตือนจะไม่ขึ้น |

#### 📢 ศูนย์แจ้งเตือน — รวมทุกเรื่องที่ต้องรู้ไว้ที่เดียว (เพิ่ม 14 ก.ย.)

**ตั้งค่าการใช้งาน → 📢 ศูนย์แจ้งเตือน** (บนสุดของหน้าตั้งค่า) · ป้ายตัวเลขโชว์ทั้งบนเมนูนั้นและบนเมนู “ตั้งค่าการใช้งาน” ในเมนูด้านข้าง

|---|---|---|

**กติกาที่ห้ามพลาด:**

##### 🕓 ประวัติการจัดการในศูนย์แจ้งเตือน (เพิ่ม 14 ก.ย.)

ส่วนท้ายของศูนย์แจ้งเตือนมี **“ประวัติการจัดการ”** ตอบคำถามว่าเรื่องไหนถูกจัดการไปแล้ว **เมื่อไหร่ · ใครกด · กี่นาทีจากตอนเกิดเรื่อง**
เก็บใน **`localStorage.taxi_notif_history_v1`** (เครื่องนี้เท่านั้น — **ไม่เขียนขึ้นเซิร์ฟเวอร์ จึงไม่กินโควตา**) เก็บล่าสุด **40 รายการ**

| เรื่อง | “ตอนเกิดเรื่อง” คำนวณจาก | จดตอนไหน |
|---|---|---|
| สมาชิกใหม่ | `__signupFirstUnseenAt` = เวลาสมัครของคนที่ยังไม่เปิดดู (เก่าสุด) | `markSignupsSeen()` ตอน **เปิดดูรายชื่อ** (ยอดก่อนล้าง) |
| คำขอสิทธิ์เพิ่ม | `requestedAt` ของคำขอที่ยัง `pending` (เก่าสุด) | `approvePermRequest` / `rejectPermRequest` |
| เที่ยวที่ยังไม่ขึ้นเซิร์ฟเวอร์ | `tripQueueOldestQueuedAt()` = เที่ยวในคิวที่เข้าคิวก่อนสุด | `drainTripSyncQueue()` เมื่อ **ส่งสำเร็จ ≥ 1 เที่ยว** |

**กติกาที่ห้ามพลาด:**

- **จดเฉพาะตอนเรื่อง “จบจริง”** — การเปิดดูเมนูเฉย ๆ ไม่ใช่การจัดการ (ไม่งั้นประวัติเต็มไปด้วยขยะ)
- **ไม่มีเรื่องค้าง (count = 0) → ห้ามจด** และ **ไม่รู้เวลาที่เกิดเรื่อง → จดพร้อม `ageMs: null`** แล้วขึ้นว่า “ไม่ทราบเวลาที่เกิดเรื่อง” — **ห้ามเดาเวลาให้ดูสวย**
- กันจดซ้ำด้วย `window.__notifLogGuard[key]` (ไม่จดคีย์เดิมซ้ำภายใน **5 วินาที**) — เพราะกดครั้งเดียวอาจวิ่งผ่าน 2 จุด
- ชื่อคนกดใช้ `notifWhoAmI()` = `myCurrentDisplayName` → `myCurrentUsername` → `fmtUname(uid)` — **ห้ามโชว์รหัส uid**

#### 🧩 จัดกลุ่มเมนูใน “ตั้งค่าการใช้งาน” — ลากข้ามหัวข้อ + สร้างหัวข้อเอง (เพิ่ม 14 ก.ย.)

กดค้างที่เมนูใน **ตั้งค่าการใช้งาน** ~0.9 วิ → เข้าโหมดลาก → **ลากเมนูข้ามหัวข้อได้ทุกหัวข้อ** (ไม่จำกัดอยู่แต่หัวข้อเดิม)
เปิดค้างไว้ทั้งหน้าตั้งค่าเพื่อให้เข้าใจโครงทั้งหมด:

| ส่วน | รายละเอียด |
|---|---|
| เข้าโหมดลาก | กดค้างที่เมนู 0.9 วิ · ออกเมื่อแตะพื้นที่ว่าง / ปุ่มปิด / ปุ่มย้อนกลับ |
| ลากข้ามหัวข้อ | ปล่อยลงในหัวข้อที่นิ้วอยู่ → เมนูย้ายไปหัวข้อนั้นทันที (จำตาม **เวลาที่นิ้ว** ไม่ใช่กึ่งกลางการ์ด) |
| ➕ สร้างหัวข้อใหม่ | ปุ่มในแถบคำแนะนำ → ตั้งชื่อ (+ ใส่ emoji ได้) → ลากเมนูไปวาง |
| ✏️ เปลี่ยนชื่อหัวข้อ | ปุ่มดินสอท้ายหัวข้อ — ใช้ได้ทั้งหัวข้อตั้งต้นและหัวข้อที่สร้างเอง |
| ✏️ แก้ข้อความเมนูรายตัว | **ปุ่มดินสอท้ายชื่อเมนู** (ในโหมดลาก · แอดมินเท่านั้น) — ใช้ได้ทั้ง **เมนูแฮมเบอร์เกอร์** และ **ตั้งค่าการใช้งาน** · กดแล้วแก้ชื่อ/คำอธิบายของเมนูนั้นได้ทันที ทางหน้าต่างเล็ก (ไม่ต้องเปิดลิสต์ยาว) |
| 🗑 ลบหัวข้อ | ปุ่มถังขยะ (เฉพาะหัวข้อที่สร้างเอง) — เมนูที่อยู่ในหัวข้อนั้นย้ายกลับหัวข้อแรกให้เอง |
| หัวข้อที่ไม่มีเมนู | **ซ่อนหัวข้อเองอัตโนมัติ** · ตอนโหมดลากจะกลับมาแสดงพร้อมช่องจุดเส้น “วางเมนูที่นี่” เพื่อให้ลากกลับเข้าได้ |

**กติกาที่ห้ามพลาด (กับดักที่เจอจริงตอนทำ):**

- หน้าตั้งค่าการใช้งาน **ห้ามกลับไปใช้ `applySavedMenuOrder()`** — ฟังก์ชันนั้นบังคับให้เมนูกลับเข้ากลุ่มเดิมทุกครั้ง ⇒ ลากข้ามหัวข้อจะไม่ติด ให้ใช้ `window.applyHubLayout()` เท่านั้น
- **ตอนลากต้องใช้ตำแหน่งนิ้ว (`drag.lastY`) ตัดสินหัวข้อ** ไม่ใช่ `getBoundingClientRect()` ของการ์ดที่ลาก — การ์ดมีการชดเชย `staticShift` ทำให้หัวข้อไม่เปลี่ยนตามนิ้ว
- **บันทึก “เมนู↔หัวข้อ” ก่อนซิงก์ Firestore** (`hubSaveCatsFromDom()` ต้องมาก่อน `saveMenuOrderToDB()`) ไม่งั้นเครื่องอื่นจะได้แผนผังหัวข้อเก่า
- รับค่าส่วนกลาง (`settings/menuOrder`) **เฉพาะเมื่อมีของจริง** — `hubItemCat` เป็น `{}` ทั่วไป อย่าเอามาทับของในเครื่อง
- ที่เก็บในเครื่อง: `hub_cats_v1` (รายชื่อหัวข้อ) · `hub_item_cat_v1` (เมนู↔หัวข้อ) · `menu_order_hub` (ลำดับ) — อ่านจากเครื่องก่อนเสมอ (ไม่ต้องรอเน็ต)
- **ซิงก์ขึ้นเซิร์ฟเวอร์พร้อมลำดับเมนู:** `settings/menuOrder` เก็บ `hubCats` + `hubItemCat` เพิ่มจาก `side`/`hub` เดิม ⇒ แอดมินจัดไว้แล้ว **เครื่องอื่นเห็นเหมือนกัน** · ซิงก์ผ่านตัวฟัง `listenGlobalMenuOrder` ที่มีอยู่แล้ว จึง**ไม่มีการอ่านเอกสารเพิ่ม** (เขียนเพิ่มเท่านั้นตอนบันทึก)

#### 🔑 PIN ยืนยันรายการสำคัญ — ตั้งเองได้ทุกบัญชี (เพิ่ม 14 ก.ย.)

ด่านยืนยันตัวตนเดิมบังคับให้พิมพ์ **รหัสผ่านเต็ม** ทุกครั้งที่แก้ข้อมูลสำคัญ (11 จุด) ซึ่งช้าเกินไปตอนอยู่หน้ารถ
ตอนนี้แต่ละบัญชี **ตั้ง PIN 6 หลักของตัวเอง** แล้วใช้ PIN ยืนยันแทนได้ · PIN ของบัญชีอื่นไม่เกี่ยวข้องกันเลย
บนมือถือ **แป้นตัวเลขเด้งขึ้นเอง** (ไม่มีคีย์บอร์ดระบบบังจอ) และลงทะเบียน **“ปลดล็อกด้วยเครื่อง”** ไว้ใช้ Face ID / ลายนิ้วมือ / PIN เครื่องแทนได้อีกทาง

| ส่วน | รายละเอียด |
|---|---|
| ตั้ง/เปลี่ยน/ลบ PIN | ตั้งค่าโปรไฟล์ → การ์ด **“PIN ยืนยันรายการสำคัญ”** (ทุกบทบาท ตั้งได้เอง รวมแอดมิน) |
| ต้องยืนยันรหัสผ่านบัญชีก่อนตั้ง | กันคนอื่นที่หยิบเครื่องที่ล็อกอินค้างไว้มาตั้ง PIN แทนเจ้าของ |
| ใช้ PIN ตอนไหน | กล่อง “ยืนยันตัวตนอีกครั้ง” จะ **ถาม PIN ก่อนอัตโนมัติ** ถ้าบัญชีนั้นมี PIN · มีลิงก์ “ใช้รหัสผ่านแทน” และ “ลืม PIN?” |
| ⌨️ แป้นตัวเลขเด้งเอง | แตะช่อง PIN → แป้นเด้งจากด้านล่าง (จุด 6 จุดติดตามที่กด) · **ไม่มีคีย์บอร์ดระบบบังจอ** · คีย์บอร์ดจริงก็พิมพ์ได้ · สั่นแผ่วทุกครั้งที่กด · ครบ 6 หลัก = ยืนยันเอง |
| ⚪ หน้าตาปุ่มบนแป้น | ปุ่ม**วงกลม** 76px กดง่ายด้วยนิ้วโป้ง · **กดแล้วติดสีชัด**: ปุ่มเลข → พื้นเขียว/ตัวเลขเข้ม · ปุ่มลบ (⌫) → พื้นแดง/ไอคอนขาว · มีวงแหวนเรืองแสงรอบปุ่มที่กด + ย่อลงเล็กน้อย (รวมตอนใช้คีย์บอร์ดจริงพิมพ์) |
| 🔓 ปลดล็อกด้วยเครื่อง | ลงทะเบียนไว้แล้วแตะที่กล่องยืนยัน → **เด้งหน้าปลดล็อกของโทรศัพท์เอง** (Face ID / ลายนิ้วมือ / PIN เครื่อง) · ตัวเลขเครื่องไม่เข้าแอปเลย · ลงทะเบียนต่อเครื่อง (credential ผูกกับอุปกรณ์) |
| ลืม PIN | กด “ลืม PIN?” → ยืนยันรหัสผ่านบัญชี → ตั้ง PIN ใหม่ (ไม่ต้องรอแอดมิน) |
| กันเดา | ผิด 5 ครั้ง → **ล็อก 5 นาที** (ผูกกับบัญชีนั้นในเครื่องนั้น) · แม้ใส่ PIN ถูกก็ไม่ผ่านระหว่างล็อก |
| รูปแบบที่ปฏิเสธ | ไม่ใช่ตัวเลข · ไม่ครบ/เกิน 6 หลัก · เลขซ้ำตัวเดียว (000000) · เลขเรียงติด (123456/654321) · ชุดเดาง่าย (123123/696969) · เลขอ่านกลับหลังได้เหมือนเดิม |

**ทำไม PIN ของ admin กับ user เป็น 123456 เหมือนกันแล้วไม่ชนกัน**

PIN **ไม่ใช่ตัวชี้ตัวตน** — แอปรู้อยู่แล้วว่ากำลังใช้บัญชีไหน (`loggedInUserId` จากตอนล็อกอิน)
จึงเก็บ `users/{uid}.pinHash` แล้วเทียบกับเอกสารของบัญชีนั้นเท่านั้น ⇒ ตัวเลขเดียวกันแต่ **salt คนละตัว → hash คนละค่า**
(แฮชด้วย `pwHash()` = PBKDF2-SHA256 100,000 รอบ + salt ต่อบัญชี · **ไม่เก็บตัวเลขจริงที่ไหนเลย**)

**กติกาที่ห้ามพลาด:**

- **ห้ามใช้ PIN เป็นตัวชี้ตัวตน** — ห้ามค้นหาผู้ใช้ด้วย `pinHash` หรือทำ index เทียบ PIN ข้ามบัญชี (กินโควตาอ่านมหาศาลและรั่วข้อมูล)
- **ห้ามเก็บ PIN ตัวเลขจริงในเครื่อง** — แคชได้เฉพาะ `taxi_pin_cache_v1 = { uid: pinHash }` เพื่อให้ออฟไลน์ยืนยันได้
- **ตั้ง/เปลี่ยน PIN ต้องยืนยันรหัสผ่านบัญชีก่อนเสมอ** — PIN เป็น “ทางลัดยืนยัน” ไม่ใช่ทางตั้ง
- **ต้องรักษา id เดิม** ของกล่อง `sysReauth` (`raPassword` · `raError` · `raDesc` · `raBtnOk` · `raBtnCancel`) — โค้ดที่เรียก `requireReauth()` 14 จุดพึ่งพามัน
- ล็อกเก็บที่ `taxi_pin_lock_v1` — เป็นรายเครื่อง **ไม่ซิงก์ขึ้นเซิร์ฟเวอร์** (เครื่องอื่นไม่ถูกหน่วงไปด้วย)
- **อ่าน PIN ของเครื่องไม่ได้ — และไม่ต้องพยายาม** เบราว์เซอร์ไม่มี API ให้อ่านรหัส/ลายนิ้วมือของโทรศัพท์ · สิ่งที่ทำได้คือให้ **หน้าปลดล็อกของเครื่องเป็นคนตรวจ** (WebAuthn) แล้วรับมาแค่ผลผ่าน/ไม่ผ่าน
- **WebAuthn รับเฉพาะ “ชื่อโดเมน” ไม่รับ IP** ⇒ ใช้ได้บน `https://baby4bot.github.io/taxi/` · ที่อยู่แบบ `127.0.0.1` จะขึ้นเตือนว่าใช้ไม่ได้ (ไม่ใช่บั๊ก)
- **แป้นตัวเลขต้องมี z-index สูงกว่ากล่องยืนยันตัวตน** (`#sysReauth` = `100050` ⇒ แป้นใช้ `300000`) ไม่งั้นแป้นจะอยู่หลังกล่อง กดไม่ได้
- **อย่าลบคลาส `.pad-key` / `.pad-del`** — กฎปุ่มวงกลมและสีตอนกดผูกกับคลาสนี้ · `pinPadPress()` เติมคลาส `pressed` เอง 130ms เพื่อให้ปุ่มติดสีตอนกดด้วยคีย์บอร์ดจริงด้วย
- `devUnlockPrompt()` เป็นการยืนยัน **ฝั่งเครื่องเท่านั้น** (ไม่มีเซิร์ฟเวอร์ตรวจลายเซ็น) — เพิ่มความยากให้คนที่หยิบเครื่อง แต่ไม่ใช่หลักฐานทางกฎหมาย

### 🛡️ หน้าจัดการผู้ใช้: เห็นข้อมูลบัญชีของสมาชิกครบ (เพิ่ม 14 ก.ย.)

กด **แก้ไข** สมาชิกคนไหน จะมีการ์ด **“ข้อมูลบัญชีของสมาชิกคนนี้”** อยู่เหนือปุ่มบันทึก:

| เห็นอะไร | แสดงเป็น | หมายเหตุ |
|---|---|---|
| 🔑 รหัสผ่านบัญชี | ตั้งไว้แล้ว / ยังไม่มี + เข้าใช้ล่าสุด | **ไม่มีตัวรหัสให้ดู** — เก็บเป็น PBKDF2 · ตั้งใหม่ได้จากช่อง “รหัสผ่าน” ด้านบน |
| 🔢 PIN ยืนยันรายการสำคัญ | ตั้งไว้ (6 หลัก) / ยังไม่ได้ตั้ง + ตั้งเมื่อ + ใครตั้งให้ | โชว์ **สถานะ** เท่านั้น · มีปุ่ม **รีเซ็ต PIN** |
| 🔓 ปลดล็อกด้วยเครื่อง | เก็บในเครื่องของสมาชิก — แอดมินมองไม่เห็น | credential อยู่ใน `localStorage` ของอุปกรณ์นั้น **ไม่ขึ้นเซิร์ฟเวอร์** ⇒ แสดงจากส่วนกลางไม่ได้ |
| ⚙️ ค่าที่สมาชิกตั้งเองได้ | ธีม · ประเภทรถ · เบิกเวลาจอด · โหมดทางด่วน · สั่น · เสียงติ๊ง · เริ่มต่ออัตโนมัติ · เต็มจออัตโนมัติ | อ่านจากเอกสารที่โหลดมาแล้ว |
| 🔄 รีเซ็ต PIN ของสมาชิก | ปุ่มแดง (โชว์เมื่อมี PIN) | **ต้องยืนยันตัวตนของผู้ทำรายการก่อน** แล้วเขียน `pinHash: ''` + บันทึก log |

**กติกาที่ห้ามพลาด:**

- **ห้ามแสดงแฮชเต็มในหน้าจอ** — รายงานได้แค่ “มี/ไม่มี” และ “ตั้งเมื่อไหร่ · ใครตั้ง” พอ (แฮชเต็มเปิดช่องให้ไล่เดารหัสนอกระบบ)
- **อ่านจาก `currentAdminUsers` เท่านั้น** — ห้ามยิง `getDoc` เพิ่มต่อการเปิดหน้าจัดการผู้ใช้ 1 ครั้ง (กินโควตาโดยไม่จำเป็น)
- **รีเซ็ต PIN ต้องยืนยันตัวตนก่อนเสมอ** (`requireReauth`) — ไม่งั้นคนที่หยิบเครื่องแอดมินที่ล็อกอินค้างไว้จะล็อกสมาชิกออกจากระบบได้
- **หลังรีเซ็ต PIN ต้องล้างแคชในเครื่องสมาชิกด้วย** — `listenToMyUser` ซิงก์ `pinCacheSet(uid, data.pinHash)` เมื่อ `pinHash` ว่าง ⇒ ถ้าไม่ล้าง **PIN เก่ายังใช้ยืนยันได้** (กับดักนี้ปิดแล้วในโค้ด · ห้ามถอดออก)

**กติกาที่ห้ามพลาด:**

- **คีย์ของ override คือ “ข้อความต้นฉบับ”** ⇒ ข้อความที่เหมือนกันจะเปลี่ยนพร้อมกันทุกจุด (เช่นคำว่า “บันทึก” 3 จุด) — ต้องตรวจจำนวน “N จุด” ที่แสดงในแต่ละแถวก่อนบันทึก
- **รหัส/คีย์ของ Map ที่จำต้นฉบับคือ text node** (`window.__txtNodes`) และ `applyTextOverrides()` เซ็ตค่าจาก **ต้นฉบับเสมอ** ⇒ ห้ามเปลี่ยนไปต่อข้อความจาก DOM ตรง ๆ ไม่งั้นลบ override แล้วข้อความจะค้าง
- **ห้ามแก้ text node** ของ `#pinPadGrid` / `.pad-key` / `.material-symbols-outlined` / `[data-txt-skip]` — เลขบนคีย์แพด PIN ต้องคงอยู่ (มีด่านใน `textOvrSkip()`)
- **ตัวเลข/เปอร์เซ็นต์ล้วนถูกข้าม** (เช่น `41%` · `15:30` · `1,481`) กันข้อความที่ระบบอัปเดตเองถูกเขียนทับ
- **บันทึก/รีเซ็ตต้องยืนยันตัวตนก่อนเสมอ** (`requireReauth`) และ **เฉพาะ Admin** เท่านั้น
- **ห้ามเช็คสิทธิ์ด้วย `window.currentUserRole`** — ตัวจริงคือ `currentUserRole` ในสคริปต์ (มีตัวช่วย `window.isAdminNow()` / `window.myRoleNow()` ให้ใช้)เคยเจอบักจริง: เมนูและปุ่มของแอดมิน **ไม่โผล่ในเครื่องผู้ใช้** เพราะเช็คตัวที่ไม่มีใครตั้งค่า (undefined ตลอด) — ทดสอบในพรีวิวแล้วเห็นขึ้น เพราะตอนเทสต์มีการตั้งค่านั้นมือ ⇒ ต้องทดสอบแบบ **ไม่ตั้งค่าอะไรเลย**
- มี **MutationObserver** ทางาน childList (debounce 180ms) จึงครอบข้อความในหน้าต่างที่เรนเดอร์ใหม่ — งานเขียนข้อความเองไม่ถูกเฝ้า ⇒ ไม่วนลูป

**กติกาที่ห้ามพลาด:**

- ⚠️ **มิเตอร์แท็กซี่ไม่รวมค่าทางด่วน** (ผู้โดยสารจ่ายค่าด่านแยก) → เทียบเฉพาะ **ส่วนมิเตอร์** (`fare − surcharges`) กับเลขบนมิเตอร์
  ห้ามเทียบยอดรวมกับมิเตอร์เด็ดขาด ไม่งั้นทุกเที่ยวที่ขึ้นทางด่วนจะรายงาน “คลาดเคลื่อน” เป็นสิบเปอร์เซ็นต์ทั้งที่ของจริงตรงกัน
- ฟีเจอร์นี้ **วัดอย่างเดียว** — ห้ามแก้สูตรหรือปรับตัวเลขค่าโดยสารให้เองจากผลเทียบ
- เขียนลง Firestore แบบ **merge เฉพาะฟิลด์ `calib`** — ห้ามทับฟิลด์อื่นของเที่ยวที่บันทึกไว้แล้ว
- เขียนไม่สำเร็จ = เข้าคิวเที่ยวเดิม (`taxi_pending_trips_v1`) แล้วลองใหม่เองเมื่อเน็ตกลับมา

### 📜 ความลื่นบนมือถือ — กฎที่ห้ามพลาด (แก้ 14 ก.ย.)

อาการที่ผู้ใช้เจอ: ในลิสต์ **ที่โปรด / ประวัติล่าสุด / ผลค้นหา** ลากขึ้นลงแล้ว “ติด” ไม่ลื่น
ต้องปล่อยนิ้วรอสักพักแล้วลองใหม่ — ต้นเหตุมี 3 อย่าง และทุกอย่างอยู่ในโค้ดนี้ด้วยกัน:

| ❌ ห้ามทำ | ✅ ทำแบบนี้ |
|---|---|
| `backdrop-filter` บน **กล่องที่กำลังเลื่อน** (`.dropdown-box`) | `@media (max-width: 900px)` ตัด blur ออก → ใช้พื้นเกือบทึบ (`rgba(18,22,34,0.985)`) — อ่านง่ายกว่าด้วย |
| `position: sticky` + `backdrop-filter` **ในลิสต์ที่เลื่อน** (`.history-header`) | ตัด blur ออก แล้วให้พื้นทึบ · sticky ได้ แต่ห้าม blur |
| `touchmove` ระดับ `window` แบบ `passive:false` + `capture` → เบราว์เซอร์ต้องรอ JS ทุกเฟรม | ติดตั้งเฉพาะเมื่อ `CSS.supports('overscroll-behavior','contain')` เป็น false (iOS เก่า) และ **ข้ามท่านั้นทั้งท่า** ถ้านิ้วเริ่มในลิสต์ที่เลื่อนได้ |

**รายละเอียดตัวดัก PTR (`lockPullToRefresh`) — หลักการคือ “ข้ามออกเร็วที่สุด”:**

- `SAFE_ZONES` = `.dropdown-box, .modal-overlay, .modal-box, .modal-content-scroll, .side-menu, …`
  ถ้า `e.target.closest(SAFE_ZONES)` → `skipGesture = true` → `onTouchMove` `return` ทันที (ไม่ `preventDefault`) ✔
- หา “กล่องที่เลื่อนขึ้นได้” **ครั้งเดียวตอน `touchstart`** (เก็บใน `scrollable`) — ห้ามเดิน DOM/`getComputedStyle` ทุกเฟรม (เดิมทำทุก `touchmove` = ต้นเหตุความหน่วง)
- ขั้นตอน `shouldBlockPull(clientY)`: ลากขึ้น/นิ่ง → `false` · ลิสต์ยังเลื่อนขึ้นได้ (`scrollTop > 1`) → `false` · อยู่หัวสุดหน้าแล้วลากลง → `true`
- PTR หลักจริง ๆ คือ CSS `html, body { overscroll-behavior: none }` — ตัว JS เป็นเพียงตัวหนุนของ iOS < 16

**🔒 ล็อกหน้าเว็บด้านหลัง ขณะลิสต์เปิดอยู่ (เพิ่มต่อจากรอบเดียวกัน):**

เดิมลิสต์เปิดอยู่แต่หน้าเว็บด้านหลังก็ยังเลื่อนได้ = **มี 2 ตัวแย่งการเลื่อนกัน** — อีกสาเหตุที่ทำให้นิ้วลากแล้วรู้สึกติด

- ล็อกเฉพาะ **document ตัวนอกสุด** เท่านั้น — ตัวลิสต์เองยังเลื่อนได้ปกติ
- CSS: `html.locked-scroll, html.locked-scroll body { overflow: hidden !important }`
- **iOS ต้องใช้ `position: fixed` ด้วย** ไม่งั้นล็อกแล้วหน้าเด้งขึ้นบนสุด → คำนวณ `--locked-scroll-top: -ระยะที่เลื่อนไป`
  แล้วคืนต่ำแหน่งด้วย `window.scrollTo(0, lockY)` ตอนปลดล็อก
- ปลดล็อกอัตโนมัติเมื่อปิดลิสต์/เลือกสถานที่ — เฝ้าด้วย **`MutationObserver` ที่ `style` ของ `#historyList`/`#suggestionList`**
  (โค้ดเดิมเซ็ต `style.display` ตรง ๆ หลายจุด → จุดเดียวจบ)
- มี **watchdog 0.8 วินาที** สร้างเฉพาะตอนล็อก → กันล็อกค้างถ้ามีเส้นทางอื่นที่ปิดลิสต์
  + ปลดล็อกเมื่อกลับมาจากพื้นหลัง (`visibilitychange`)
- ตรวจว่าไม่ค้าง: `window.__pageScrollLocked` · `html.locked-scroll` · `getComputedStyle(document.body).overflowY`

**เพิ่มเติมที่กล่องรายการ:** `-webkit-overflow-scrolling: touch` (โมเมนตัมแบบ iOS เก่า) · `overscroll-behavior: contain` (ลากจนสุดลิสต์แล้วไม่ลากหน้าเว็บต่อ)
· `transform: translateZ(0)` (ยกเป็นเลเยอร์ของตัวเอง → เลื่อนแล้วไม่ต้อง repaint พื้นหลัง)

> ⚠️ ตรวจด้วยตา: เปิดหน้านี้ในมือถือ → แตะช่องค้นหา → ลากในลิสต์ต้องลื่นต่อเนื่อง
> และห้ามให้หน้าจอทั้งหน้าถูกดึงลงมารีเฟรชในกล่องที่กำลังเลื่อน

## ⏱️ ความน่าเชื่อถือตอนขับจริง (จุดที่ออกแบบมาพิเศษ)

แอปนี้ต้องทนกับสถานการณ์จริงหน้ารถ จึงมีกลไกเฉพาะเหล่านี้:

- 🔁 **เริ่มต่อเที่ยวค้างอัตโนมัติ** — เผลอปิดแอป/รีเฟรช/ย่อหน้าต่างไว้ เปิดใหม่แล้วมิเตอร์เดินต่อให้
  พร้อมเปิดจอมิเตอร์ใหญ่และ **เสียง + สั่นเตือน** ว่ามิเตอร์เริ่มต่อแล้ว (ตั้งค่าเปิด/ปิดได้)
- 🧷 **กันระยะทาง–เวลารถติดเพี้ยนหลังปิด/ย่อแอป** — ระบบจำ "ฐานหลักฐาน" ณ วินาทีที่แอปถูกซ่อน/ปิด
  (ระยะทาง + เวลารถติด + ตำแหน่ง) แล้วเบิกคืนจากฐานนั้นครั้งเดียว → ตัวเลขไม่บวมและไม่หายข้ามรีเฟรช
- 🚫 **ล็อกจอ/ปิดแอป = ไม่นับเวลารถติดเอง** — ไม่มี GPS fix สดใหม่ = ไม่นับต่อ (เดิมนับ 1 วิ/วิ ตลอดช่วงที่ล็อกจอ)
  เคสจริง: ล็อกจอทั้งเที่ยว 10.7 กม. → แอปขึ้น `18:03` แต่มิเตอร์จริง `4:54` → 149 บาท แทน 113
  ของจริงคือ **เบิกคืนเมื่อมีหลักฐานครั้งถัดไป** — จอดจริงก็ได้ครบ · วิ่งจริงก็ไม่ถูกคิดเป็นเวลาจอด
- ⚙️ **ประเมินเวลารถติดช่วงแอปปิดจาก "ความเร็วล้อหมุนจริงของเที่ยวนี้"** ไม่ใช่ค่าคงที่ 65 กม./ชม. อีกแล้ว
  ลำดับความเชื่อถือ: ① เวลาวิ่งโล่งจริงของช่วงนั้นจาก TomTom → ② ความเร็วล้อหมุนที่วัดจาก GPS ของผู้ขับคนนี้
  → ③ ไม่มีข้อมูลเลย = 25% ของช่วง (เทียบเคสจริง: ปิดแอป 13 นาที วิ่ง 5 กม. — เดิมเบิก 8:09 → ใหม่ 1:44)
- 🧾 **การ์ดหลักฐานการเบิกคืน** — ในหน้าสรุปค่าโดยสารมีหัวข้อบอกช่วงที่แอปถูกปิดและยอดที่เบิกไป เพื่อตรวจย้อนหลังได้
- 🎯 **ปรับเทียบมิเตอร์จริง** — กรอก กม.+ราคา จากมิเตอร์ตอนจบเที่ยว แล้วหน้าประวัติสรุปส่วนต่างเฉลี่ยเป็น %
  พร้อมบอกว่าแอปคิดสูงกว่าหรือต่ำกว่ามิเตอร์จริง (เทียบเฉพาะส่วนมิเตอร์ — ไม่รวมค่าทางด่วน)
- ⏳ **จำกัดเวลาจอดที่เบิกหลังปิดแอปได้** — กันค่าโดยสารบวมถ้าลืมจบเที่ยวข้ามคืน

### 🧪 ตรวจประวัติเวอร์ชันก่อนปล่อย (รันได้จากเครื่อง)

```
powershell -NoProfile -ExecutionPolicy Bypass -File tests/changelog-check.ps1
→ ... -Live                            เทียบกับข้อมูลจริงบน Firestore ทีละบรรทัด
→ ... -Index "index - 122 ....html"    ตรวจไฟล์เวอร์ชันอื่น (เช่นไฟล์สำรอง) แทน index.html
→ ... -MaxLen 90                       เกณฑ์ความยาวต่อหัวข้อ (ค่าเริ่มต้น 90)
→ ... -UpdateBaseline                  รับรูปร่างปัจจุบันเป็นมาตรฐานใหม่ (ใช้เมื่อ “มีหัวข้อเพิ่มจริง”) 
```

ตรวจ 8–9 ข้อ: **วันหาย** (การ์ดวันที่เคยมีหายไป) · **จำนวนหัวข้อต่อวันเปลี่ยน** · วันใหม่ไม่ตรงกับ
`APP_RELEASE_DATE` · ข้อความซ้ำ · เลขเวอร์ชันเรียงผิด · ข้อความยาวเกินเกณฑ์ · และถ้าใส่ `-Live`
จะเทียบข้อความกับ Firestore ทีละบรรทัด (ไม่ตรงก็ฟ้อง)

**กติกามาตรฐานจำนวนหัวข้อ (`tests/changelog-baseline.json`):**

- **วันเก่า ล็อกตาย** — หัวข้อหาย/เพิ่ม/สลับ ล้วนเป็น FAIL (กันเคส “วันที่ 11 หาย”)
- **วันนี้ (`APP_RELEASE_DATE`) เพิ่มหัวข้อได้** ระหว่างวัน (PASS พร้อมข้อความเตือน) — แต่ **ห้ามลด**
  ถ้าลด → FAIL · เมื่อปิดวันแล้วควรสั่ง `-UpdateBaseline` เพื่อล็อกจำนวนจริงไว้ ไม่งั้นเดย์หน้าการเพิ่มจะไม่ถูกตรวจ
- **ห้ามสร้างมาตรฐานใหม่เพื่อกลบ error** — ถ้าจะ `-UpdateBaseline` ต้องเขียนเหตุผลในคอมมิต
- ตรวจแล้วว่า FAIL จริงทั้ง 2 ทาง: ลบการ์ดวัน (DAY GONE) · ลดหัวข้อวันนี้ (9 → 8)
คืนค่า `exit 0` เมื่อผ่าน / `exit 1` เมื่อมีข้อใดไม่ผ่าน — ข้อความไทยของจุดที่ผิดเขียนเป็นไฟล์ UTF-8
ไว้ที่ `tests/changelog-check-report.txt` อ่านรู้เรื่องแน่นอน

### 🔐 ด่านยืนยันตัวตนซ้ำ (Re-auth) — 14 ก.ย. 2569

ก่อนทำรายการที่แก้ข้อมูลสำคัญ แอปจะถาม **รหัสผ่านของบัญชีที่ล็อกอินอยู่** ทุกครั้ง
(ใช้ `window.requireReauth(reason)` → ตรวจกับ `pwVerify()` จริง · ผิด 3 ครั้ง = ยกเลิกเอง)

| กลุ่มงาน | ตัวอย่าง |
|---|---|
| **แก้สมาชิก** | เพิ่ม/แก้ชื่อ–รูป–QR–รหัสผ่าน–ตำแหน่งของสมาชิก · ลบบัญชี · ระงับบัญชี · กำหนดวันสมัครย้อนหลัง |
| **เปลี่ยนสิทธิ์** | อนุมัติคำขอสิทธิ์ · บันทึกสิทธิ์ของตำแหน่ง · รายการสิทธิ์ + ลำดับเมนู |
| **ลบรูป** | รูปโปรไฟล์/QR รับเงิน ของตัวเองและของสมาชิก (รวมทั้งอัปโหลดทับ) |
| **ค่าที่มีผลกับทุกคน** | หน้าจอโหลด · ข้อความแจ้งเตือน |

- **ทำไม:** เครื่องที่ล็อกอินค้างไว้ (วางในแท็กซี่/ให้คนอื่นยืม) ใครหยิบได้ก็แก้ข้อมูลได้ทันที — ด่านนี้ปิดช่องนั้น
- **ยืนยันสำเร็จแล้วผ่อนผัน 2 นาที** สำหรับงานหลายขั้นตอนติดกัน (กันพิมพ์รหัสซ้ำรัว ๆ)
- **ออฟไลน์:** ตรวจรหัสไม่ได้ → ระบบ **ถามยืนยันจากผู้ใช้** ไม่ปล่อยผ่านเงียบ ๆ และไม่ล็อกการทำงานตอนเน็ตหลุด
- ธีม/การตั้งค่าที่แก้บ่อย (เต็มจอ · สั่น · เสียง · ประเภทรถ) **ไม่ต้องยืนยัน** — ไม่เกี่ยวกับความปลอดภัยของบัญชี
- รายการทั้งหมด + กติกาห้ามละเมิดอยู่ที่ [`SECURITY.md` หัวข้อ 9](SECURITY.md)
